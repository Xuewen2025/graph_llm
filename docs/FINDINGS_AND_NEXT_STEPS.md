## 1. 实验结论

实验设置：AV2 验证集 2000 个场景；Qwen3-0.6B + LoRA；2 万条训练场景，训练 3 个 epoch。指标是 ADE@6s，单位米，越低越好。带 \* 的差异 95% 置信区间不含 0（配对 bootstrap）。

| 变体 | 全部 | 前方 25 m 内有车 (n=600) | 难预测场景 (n=400) |
|---|---|---|---|
| 基线：纯文本（坐标列表） | 1.998 | 1.752 | 3.224 |
| + 历史/当前图，写成文本 | 2.028 | 1.813 | 3.251 |
| **+ 预测的未来图，写成文本（fut）** | **1.776**（−11%\*） | **1.445**（−17.5%\*） | **2.819** |
| B：预测器去掉物体之间的边 | 1.870（比 fut +5.3%\*） | 1.626（+12.5%\*） | 2.972 |
| A：fut + 8 个池化图 token | 1.794（+1.0%） | 1.438 | 2.906 |
| N：fut + 逐节点图 token（对齐节点名）+ 微调编码器 | 1.767（−0.5%，不显著） | 1.443 | 2.753 |
| + CoT | 2.062（比 fut +16%\*） | 1.757 | 3.264 |
| 完整模型（CoT + 图 token + [PLAN] 回归头） | 2.169 | 1.627 | 4.045 |
| 完整模型修复版 v2 | 2.136 | 1.696 | 3.820 |
| 匀速外推（参考） | 3.613 | | |

其他对照：
- **数据少时（2000 条训练样本）**：基线 2.434，+ 历史图 2.388（−1.9%），+ 未来图 2.166（−11%）。
- **模型规模**（原版完整模型，1.7B 和 4B 只训了 1 个 epoch）：每个尺寸上完整模型都比同尺寸基线差。
- **纯 GNN 预测器**（不用 LLM、没有导航指令、也不是专门为自车训练的）：自车 ADE@3s 为 0.550，和 LLM 基线的 0.544 持平。加了未来图的 LLM 是 0.497。

### graph 有没有用？

1. **有用：物体之间的关系建模，也就是 GNN 的消息传递。** 只去掉物体之间的边，未来图带来的收益就少了约一半，交互场景里误差升高 12.5%，统计上显著。论文"图适合表征物体关系"的动机，在这个层面得到了支持。
2. **没用：把图作为一种输入格式给 LLM 看。** 三种做法都没有超过纯文本：
   - 历史图写成三元组文本；
   - 池化成 8 个图 token；
   - 逐节点图 token。
   
   原因是文本里已经有精确的自车坐标系坐标，加上 2 万条数据微调，LLM 能自己学会计算几何关系，图信息就重复了。
3. **CoT 蒸馏有害。** 推理标签是教师模型看了真实轨迹之后写的"事后解释"。测试时小模型要先自己生成推理，生成错了会带偏轨迹。完整模型变差主要就是这个原因。
4. **误差的大头在纵向**：纵向 1.85 m，横向 0.36 m。也就是说，难点在速度决策（跟车、让行），这本质上是交互问题。
5. **论文里基线和完整模型的大差距没有复现。** 论文基线的 FVR 是 99.85%，很可能没有经过微调。我们这边认真微调过的文本基线本身就很强。

局限：只做了开环评测；数据集是 AV2，不是 nuPlan；每个配置只跑了一个随机种子。

## 2. 建模建议

核心思路：**让图负责计算，让 LLM 负责决策，并且 LLM 的决策要落到具体的图节点上。**

```
场景图 G ─► 时空 GNN（交互建模）─► 节点向量 + 多模态未来预测
                │                           │
                ▼                           ▼
        LLM 决策层：输出指向图节点的语义决策
        例："沿 L1→L3，跟随 A2，目标 6 m/s，在 X1 前让行"
                │
                ▼
        图条件轨迹解码器：路径沿车道图（横向）+ 速度曲线（纵向）
```

1. **输出拆成"车道路径 + 速度曲线"。** 路径通过在车道节点上做分类得到，直接利用车道图结构；速度曲线以被跟随或需要让行的对象的预测轨迹为条件。这样针对的是误差大头（纵向），而且轨迹天然平滑，FVR 会下降。
2. **LLM 只输出离散决策**，内容包括：目标车道 `L_k`、交互对象 `A_k`、行为（跟随、让行、超车、停车）、速度档位。
   - 标签可以从真实轨迹自动推导，不需要教师模型。
   - 只有在这种"指向节点"的任务里，逐节点图 token 才有发挥空间。
3. **CoT 要么去掉，要么从图中可验证的事实生成，要么放到轨迹之后当作解释。**
4. **预测和规划联合建模。** 先生成几条候选自车轨迹，用 GNN 预测其他车在每种情况下的反应，再由 LLM 或打分器挑出最好的一条。

## 3. 下一步实验（按优先级）

| 优先级 | 实验 | 目的 | 预计耗时 |
|---|---|---|---|
| **P1** | **纯 GNN 规划器**：在 `STGraphPredictor` 上加一个自车专用的 6 s 规划头（12 步），输入加上导航指令的 one-hot，只用自车损失或加大自车损失权重 | 确定"只用图"的上限。GNN 预测器不做任何专门训练，3 s 时就已经和 LLM 基线持平，所以它很可能是一个很强的基线 | 开发 1 小时 + 训练约 15 分钟 |
| **P2** | **LLM 决策 + 图解码器**：从真实轨迹自动推导决策标签（目标车道、前车、行为、速度档位），训练 LLM 输出决策，GNN 解码器按决策生成轨迹 | 检验 LLM 和图各司其职的方案，以及逐节点图 token 在"指向节点"时是否有用 | 开发约 1 天 + 训练 3 小时 |
| P3 | 节点 token 替代坐标文本：提示里只保留节点名和节点 token | 在精度不变的前提下，看输入 token 能减少多少（现在提示约 1500 token） | 约 3 小时 |
| P4 | 多模态输出（minADE）、交互场景子集、闭环评测（nuPlan / interPlan） | 开环 L2 体现不出交互推理的价值 | 闭环需要 nuPlan |

P1 的实现提示：
- `sage/config.py` 里 `TF=6`，即 3 s，是所有物体共用的预测长度。
- 自车规划头可以单独做：读 GRU 状态 `ht[:,0]` 加导航指令，用 MLP 输出 12×2 的位移，再累加成轨迹。做法可以参考 `sage/llm.py: decode_head`。
- 训练数据直接用 `PredictorDataset`，再加上 `ego_future` 作为监督信号。
- 评测复用 `sage/metrics.py: summarize`，结果和 `outputs/llm_fut` 对比。

## 4. 从 GitHub 恢复环境

```bash
git clone git@github.com:Xuewen2025/graph_llm.git sage_drive   # 需要 deploy key，或用 https + token
cd sage_drive
bash scripts/restore.sh
```

`restore.sh` 会依次完成：
1. 创建 venv；
2. 按 `splits/*_ids.txt` 精确下载同一批 2.2 万个 AV2 场景（公开 S3，不需要账号，约 5.4 GB）；
3. 预处理；
4. 用仓库里的预测器生成未来预测、提示记录和节点映射，以及实验 B 用的数据缓存；
5. 最后用 200 个场景快速验证，ADE@6s 应该接近 1.78。
