## 1. 实验结论

实验设置：AV2 验证集 2000 个场景；Qwen3-0.6B + LoRA；2 万条训练场景，训练 3 个 epoch。指标是 ADE@6s，单位米，越低越好。带 \* 的差异 95% 置信区间不含 0（配对 bootstrap）。

| 变体 | 全部 | 前方 25 m 内有车 (n=600) | 难预测场景 (n=400) |
|---|---|---|---|
| 基线：纯文本（坐标列表） | 1.998 | 1.752 | 3.224 |
| + 历史/当前图，写成文本 | 2.028 | 1.813 | 3.251 |
| **+ 预测的未来图，写成文本（fut）** | **1.776**（−11%\*） | **1.445**（−17.5%\*） | **2.819** |
| B：预测器去掉物体之间的边 | 1.870（比 fut +5.3%\*） | 1.626（+12.5%\*） | 2.972 |
| A：fut + 8 个池化图 token | 1.794（+1.0%） | 1.438 | 2.906 |
| N：fut + 逐节点图 token（对齐节点名）+ 微调编码器 | 1.767（−0.5%，不显著） | 1.443 | 2.753 |
| + CoT | 2.062（比 fut +16%\*） | 1.757 | 3.264 |
| 完整模型（CoT + 图 token + [PLAN] 回归头） | 2.169 | 1.627 | 4.045 |
| 完整模型修复版 v2 | 2.136 | 1.696 | 3.820 |
| 匀速外推（参考） | 3.613 | | |

其他对照：
- **数据少时（2000 条训练样本）**：基线 2.434，+ 历史图 2.388（−1.9%），+ 未来图 2.166（−11%）。
- **模型规模**（原版完整模型，1.7B 和 4B 只训了 1 个 epoch）：每个尺寸上完整模型都比同尺寸基线差。
- **纯 GNN 预测器**（不用 LLM、没有导航指令、也不是专门为自车训练的）：自车 ADE@3s 为 0.550，和 LLM 基线的 0.544 持平。加了未来图的 LLM 是 0.497。

### graph 有没有用？

1. **有用：物体之间的关系建模，也就是 GNN 的消息传递。** 只去掉物体之间的边，未来图带来的收益就少了约一半，交互场景里误差升高 12.5%，统计上显著。论文"图适合表征物体关系"的动机，在这个层面得到了支持。
2. **没用：把图作为一种输入格式给 LLM 看。** 三种做法都没有超过纯文本：
   - 历史图写成三元组文本；
   - 池化成 8 个图 token；
   - 逐节点图 token。
   
   原因是文本里已经有精确的自车坐标系坐标，加上 2 万条数据微调，LLM 能自己学会计算几何关系，图信息就重复了。
3. **CoT 蒸馏有害。** 推理标签是教师模型看了真实轨迹之后写的"事后解释"。测试时小模型要先自己生成推理，生成错了会带偏轨迹。完整模型变差主要就是这个原因。
4. **误差的大头在纵向**：纵向 1.85 m，横向 0.36 m。也就是说，难点在速度决策（跟车、让行），这本质上是交互问题。
5. **论文里基线和完整模型的大差距没有复现。** 论文基线的 FVR 是 99.85%，很可能没有经过微调。我们这边认真微调过的文本基线本身就很强。

局限：只做了开环评测；数据集是 AV2，不是 nuPlan；每个配置只跑了一个随机种子。

## 2. 建模建议

核心思路：**让图负责计算，让 LLM 负责决策，并且 LLM 的决策要落到具体的图节点上。**

```
场景图 G ─► 时空 GNN（交互建模）─► 节点向量 + 多模态未来预测
                │                           │
                ▼                           ▼
        LLM 决策层：输出指向图节点的语义决策
        例："沿 L1→L3，跟随 A2，目标 6 m/s，在 X1 前让行"
                │
                ▼
        图条件轨迹解码器：路径沿车道图（横向）+ 速度曲线（纵向）
```

1. **输出拆成"车道路径 + 速度曲线"。** 路径通过在车道节点上做分类得到，直接利用车道图结构；速度曲线以被跟随或需要让行的对象的预测轨迹为条件。这样针对的是误差大头（纵向），而且轨迹天然平滑，FVR 会下降。
2. **LLM 只输出离散决策**，内容包括：目标车道 `L_k`、交互对象 `A_k`、行为（跟随、让行、超车、停车）、速度档位。
   - 标签可以从真实轨迹自动推导，不需要教师模型。
   - 只有在这种"指向节点"的任务里，逐节点图 token 才有发挥空间。
3. **CoT 要么去掉，要么从图中可验证的事实生成，要么放到轨迹之后当作解释。**
4. **预测和规划联合建模。** 先生成几条候选自车轨迹，用 GNN 预测其他车在每种情况下的反应，再由 LLM 或打分器挑出最好的一条。

## 3. 下一步实验（按优先级）

| 优先级 | 实验 | 目的 | 预计耗时 |
|---|---|---|---|
| **P1** | **纯 GNN 规划器**：在 `STGraphPredictor` 上加一个自车专用的 6 s 规划头（12 步），输入加上导航指令的 one-hot，只用自车损失或加大自车损失权重 | 确定"只用图"的上限。GNN 预测器不做任何专门训练，3 s 时就已经和 LLM 基线持平，所以它很可能是一个很强的基线 | 开发 1 小时 + 训练约 15 分钟 |
| **P2** | **LLM 决策 + 图解码器**：从真实轨迹自动推导决策标签（目标车道、前车、行为、速度档位），训练 LLM 输出决策，GNN 解码器按决策生成轨迹 | 检验 LLM 和图各司其职的方案，以及逐节点图 token 在"指向节点"时是否有用 | 开发约 1 天 + 训练 3 小时 |
| P3 | 节点 token 替代坐标文本：提示里只保留节点名和节点 token | 在精度不变的前提下，看输入 token 能减少多少（现在提示约 1500 token） | 约 3 小时 |
| P4 | 多模态输出（minADE）、交互场景子集、闭环评测（nuPlan / interPlan） | 开环 L2 体现不出交互推理的价值 | 闭环需要 nuPlan |

P1 的实现提示：
- `sage/config.py` 里 `TF=6`，即 3 s，是所有物体共用的预测长度。
- 自车规划头可以单独做：读 GRU 状态 `ht[:,0]` 加导航指令，用 MLP 输出 12×2 的位移，再累加成轨迹。做法可以参考 `sage/llm.py: decode_head`。
- 训练数据直接用 `PredictorDataset`，再加上 `ego_future` 作为监督信号。
- 评测复用 `sage/metrics.py: summarize`，结果和 `outputs/llm_fut` 对比。

## 5. P1 结果：纯 GNN 规划器（2026-11-26）

代码：`sage/gnn_planner.py`、`scripts/train_gnn_planner.py`、`scripts/p1_jobs.sh`、`scripts/compare_p1.py`。完整表格见 `outputs/p1_results.md`。
模型：`STGraphPredictor` + 自车规划头（自车 query = 自车 GRU 状态 + 导航指令 + 当前运动状态，2 层 cross-attention 读取所有节点；节点 key 加上该节点的预测未来状态；输出相对匀速外推的 12 步残差）。损失 = 自车 6 s 损失 + 全体物体 3 s 预测损失。30 epoch，单卡约 15 分钟，单种子。

| 变体 | ADE@6s | 前车 <25 m | 难预测 | FVR | 碰撞 |
|---|---|---|---|---|---|
| llm_raw | 1.998 | 1.752 | 3.224 | 8.5% | 5.20% |
| llm_fut（之前最好的 LLM） | 1.776 | 1.445 | 2.819 | 8.9% | 4.20% |
| **gnn_plan**（预测器初始化 + 导航） | **1.507**（比 llm_fut −15.2%\*） | **1.125**（−22.1%\*） | **2.222**（−21.2%\*） | 14.6% | 3.45% |
| gnn_plan_nonav（去掉导航指令） | 1.700（+12.8%\*） | 1.398 | 2.638 | 15.3% | 3.95% |
| gnn_plan_scratch（从零训练） | 1.471（−2.3%，不显著） | 1.107 | 2.272 | 14.1% | 2.65% |
| gnn_plan_noaa（去掉物体之间的边） | 1.478（−1.9%，不显著） | 1.142 | 2.158 | 14.5% | 3.50% |

结论：
1. **纯 GNN 规划器显著好于所有 LLM 变体**，三个子集都显著，交互/难预测场景优势更大。15 分钟训练 vs LLM 1.5–2.5 小时。
2. **FVR 变差**（14.6%，GT 自身 11%）：直接回归的轨迹不够平滑。可以加平滑/运动学约束，或改成速度曲线 + 路径的输出（P2 思路）。
3. **导航指令很关键**（去掉后 +12.8%）。注意：导航指令由 GT 未来轨迹推出，"stop / stay" 会泄露速度信息；所有变体（含 LLM）都用了它，比较公平，但绝对数值偏乐观。
4. **预训练初始化不需要**，从零训练一样好。
5. **去掉物体之间的边在这里不再有影响**。之前实验 B 的结论（"消息传递很重要"）是在"预测器 → 文本 → LLM"链路里得到的；这里规划头的 cross-attention 直接读取所有节点（含其预测未来），已经覆盖了自车与他车的交互。所以更准确的说法是：重要的是"有某种结构化的交互建模"，不一定非要 agent-agent 边。

对后续的影响：P2（LLM 决策 + 图解码器）需要以 gnn_plan（1.507）为基线，而不是 llm_fut。LLM 要证明自己有用，得在这个基线上再带来提升。

## 6. P2 结果：LLM 决策 + 图解码器（2026-11-26）

代码：`sage/decision.py`（从 GT 自动推导决策标签）、`scripts/build_decisions.py`、`sage/gnn_planner.py: DecisionGNNPlanner`、`scripts/train_dec_planner.py`、`scripts/gen_llm_dec.py`、`scripts/p2_jobs.sh`；LLM 变体 `dec`（`sage/llm.py`，从 llm_fut LoRA 继续训 1 epoch）。

决策 = 6 s 时所在车道 L_k（35% none）+ 路径上的前车/让行对象 A_k（23% 有）+ 3 s / 6 s 速度档（2 m/s 一档）。只能指向提示里点名的节点，GNN 和 LLM 的候选集合相同。

| 解码器的决策来源 | ADE@6s | 车道准确率 | 前车准确率 | 3 s 速度档 | 6 s 速度档 |
|---|---|---|---|---|---|
| 真实决策（上限） | 0.714 | – | – | – | – |
| GNN 自己的决策头 | 1.541 | **86.4%** | **91.6%** | **72.1%** | **59.8%** |
| LLM（Qwen3-0.6B，dec） | 1.696 | 80.5% | 91.2% | 69.5% | 56.1% |
| 参考：P1 gnn_plan（无决策） | 1.507 | | | | |
| 参考：llm_fut（LLM 直接出轨迹） | 1.776 | | | | |

配对 bootstrap（ADE@6s）：LLM 决策比 GNN 决策差 +10.1%\*；GNN 决策 + 解码器 vs P1 +2.3%（不显著）；LLM 决策 + 解码器比 llm_fut 好 −4.5%\*。

结论：
1. **决策表示本身信息量很大**：给对决策，误差从 1.5 降到 0.71。瓶颈完全在"选对决策"，尤其是速度档（6 s 只有约 60% 准）。
2. **LLM 选决策不如 GNN**：4 项准确率全部更低，轨迹误差差 10%。即使任务改成"指向节点的离散决策"，LLM 依然没有超过图模型。
3. **加决策层对纯 GNN 没有帮助**（1.541 vs 1.507，不显著），但让 LLM 只做决策、由图解码轨迹，比 LLM 直接写轨迹好 4.5%。
4. 速度和前车的不确定性本质上是多模态的；单一 argmax 决策 + L2 指标对这种结构不友好。下一步更有意义的是多模态（top-k 决策 → k 条轨迹，minADE）或闭环评测。

## 7. LLM 的价值在哪里？（实验 A / B / D）

背景：P1/P2 显示 GNN 规划器在精度上全面优于 LLM。下面检验 LLM 可能有价值的三个方向。

### B. 互补性（对照：第二个 GNN 种子）
| 组合 | 误差相关 | 逐场景 oracle 选择 | 简单平均 |
|---|---|---|---|
| GNN s1 + GNN s2 | 0.88 | 1.258 | 1.483 |
| GNN s1 + LLM(llm_fut) | 0.72 | 1.177 | 1.495 |
| GNN s1 + GNN s2 + LLM | | | 1.453 |

三者平均 − 两 GNN 平均 = −0.030 m，95% CI [−0.054, −0.006]，显著。LLM 带来种子噪声之外的多样性，但直接平均的收益很小（≈2%）。若要接近 1.18 的 oracle，需要学一个选择器/门控。

### A1. 少数据（2k 训练场景）
gnn_plan 1.826，llm_fut 2.166，llm_raw 2.434，llm_hist 2.388。从 20k 降到 2k，GNN 退化 +21%，LLM 退化 +22%：少数据下 LLM 没有优势。

### A2. 跨城市（训练时去掉 Pittsburgh，预测器也只用源城市训练）
- GNN：其他城市 1.495，Pittsburgh 1.567（val 409 个）/ 1.522（train split 4187 个）。和用全部城市训练的 GNN 相比，在同样 409 个 Pittsburgh 场景上 +0.079（+5.3%，CI [−0.033, 0.193]，不显著）。城市间的域差距本身就很小。
- LLM：其他城市 1.873，Pittsburgh 1.852（val）/ 1.875（train split）。去掉 Pittsburgh 后训练数据只剩 15.8k，所以 LLM 在其他城市上也变差了 +0.100（+5.6%）。
- OOD 专属惩罚 = Pittsburgh 上的退化 − 其他城市上的退化：GNN +0.095（CI [−0.03, 0.22]），LLM −0.034（CI [−0.13, 0.05]）。两者之差 −0.13，CI [−0.29, +0.02]，**不显著**。
- 绝对水平：在 OOD 的 Pittsburgh 上 GNN 仍领先 0.285 m（1.567 vs 1.852，CI [0.12, 0.45]）。
- 结论：LLM 的 OOD 退化可能略小（趋势），但不显著，远不足以弥补它的精度差距。

### D. 语言指令接口（指令由 GT 决策生成；val 上有 seen / unseen 两种措辞，提到的内容完全相同）
- GNN 基线：用冻结的 Qwen3-0.6B 对指令做 mean-pool 得到嵌入，经 MLP 注入 query，再由自己的决策头加解码器出轨迹。
- LLM：在 llm_dec 基础上加指令再微调 1 epoch，生成决策后交给同一个 GNN 解码器。

| 指令 | GNN ADE@6s | LLM→解码器 ADE@6s | GNN 决策准确率 lane/lead/v3/v6 | LLM 决策准确率 |
|---|---|---|---|---|
| seen | **0.898** | 0.945 | 94.7/95.8/90.7/88.9 | 92.3/96.5/90.5/87.8 |
| unseen | 1.456 | **0.976** | 83.6/91.2/75.0/63.3 | 88.9/94.3/90.1/87.0 |

- unseen 上 LLM − GNN = −0.480 m，CI [−0.554, −0.408]，非常显著。GNN 从 seen 到 unseen 退化 +0.558（+62%），LLM 只退化 +0.031（+3%）。
- GNN 的退化几乎全部来自含速度的指令（981 个场景：0.88 → 1.88）。冻结嵌入读不懂改写后的数字表述（"roughly 8 metres per second"），LLM 可以。
- 不跟随指令时的参考值：P1 gnn_plan 1.507。所以 LLM 加指令（unseen）比它好 0.531 m。
- 局限：GNN 基线的文本编码器较弱。更强的基线（微调过的句向量模型，或规则解析器）可能缩小差距。另外指令是模板合成的，不是真人语言。

### 小结
- 在纯模仿精度、少数据、跨城市这几个方向上，LLM 都没有优势。跨城市只有不显著的趋势。
- 有价值的方向：(1) 与 GNN 互补，信号小但显著；(2) **语言/指令接口**：对没见过的措辞具有鲁棒性，这是 GNN 加固定文本编码器做不到的。
- 建议把论文定位改成："GNN 负责几何与精度，LLM 负责语义决策与人机指令"。主要卖点是 D，B 作为辅助。

## 8. 实验 1：给 VLM 输入 image 还是 graph？（核心假设）

设置：Qwen2.5-VL-3B-Instruct，在语言模型上加 LoRA(r=16)；视觉塔冻结，merger 可训练；使用 chat 模板。四组预算完全相同：2 个 epoch，有效 batch 16，lr 2e-4。
- 所有组都输入相同的任务说明、自车状态（速度、加速度、yaw-rate、过去 2 s 位置）和导航指令。
- BEV 图像由 `sage/bev.py` 渲染，448×448，约 0.2 m/px，信息量与 hist graph 文本相同。
- 代码：`sage/vlm.py`、`scripts/train_vlm.py`、`scripts/vlm_jobs.sh`、`scripts/compare_vlm.py`。完整表格见 `outputs/vlm_results.md`。

| 组 | ADE@6s | 有前车 | 困难场景 | 转弯 (n=120) | FVR | 碰撞 |
|---|---|---|---|---|---|---|
| vlm_raw（无关系的文本列表） | 1.995 | 1.691 | 3.301 | 3.627 | 8.3% | 5.30% |
| vlm_img（BEV 图像） | 2.038 | 1.757 | 3.312 | 3.729 | 9.4% | 5.20% |
| vlm_hist（graph 文本） | 1.988 | 1.679 | 3.225 | 3.755 | 8.3% | 5.15% |
| vlm_imghist（图像 + graph） | **1.945** | **1.661** | **3.131** | **3.443** | 8.5% | 5.35% |
| 参考：llm_raw 0.6B | 1.998 | | | | | |
| 参考：gnn_plan | 1.507 | | | | | |

配对 bootstrap（ADE@6s，负数表示前者更好，`*` 表示显著）：
- graph − image：−0.050（−2.5%），CI [−0.103, +0.002]，边缘不显著；有前车子集 −4.4%，也不显著。
- (image+graph) − image：−0.093（−4.6%）*；困难场景 −5.5% *。
- (image+graph) − graph：−0.043（−2.2%）*；转弯 −8.3% *。
- graph − raw：−0.007，不显著。image − raw：+0.044（+2.2%），边缘不显著。

初步解读：
- 方向上 graph 比 image 好，image+graph 最好且显著，但幅度都很小（2–5%）。
- graph 文本与 raw 文本几乎一样，说明"结构化"本身在文本中没有额外帮助。
- 3B VLM 的最好结果（1.945）与 0.6B 文本 LLM（1.998）差不多，都远不如 GNN（1.507）。
- 疑点：所有组都在 2.0 左右，模型可能主要依赖自车状态外推，场景信息利用很少。为此增加对照组 vlm_ego（只给自车状态和导航，不给场景），结果见下。

### 对照组 vlm_ego（只给自车状态和导航，不给场景）：ADE@6s 2.096
"场景带来的收益" = ego − 该组，全部显著：

| 组 | 场景收益（全部） | 有前车 | 困难场景 | 转弯 |
|---|---|---|---|---|
| img | 0.058（2.8%） | 0.035（n.s.） | 0.116（n.s.） | 0.436 |
| raw | 0.101（4.8%） | 0.101 | 0.127（n.s.） | 0.538 |
| hist（graph） | 0.108（5.1%） | 0.113 | 0.203 | 0.410 |
| imghist | 0.151（7.2%） | 0.132 | 0.296 | 0.722 |

- 疑点得到证实：直接输出轨迹时，VLM 利用场景信息只带来 3–7% 的提升，误差主体来自对自车运动的外推。GNN（1.507）说明场景中其实还有很多可利用的信息。
- 在这个有限的场景收益里，graph 提取到的约是 image 的 1.9 倍（0.108 vs 0.058），在有前车、困难场景的子集上差距更大；二者结合最好（0.151）。
- 但 graph 文本与 raw 文本基本持平，说明优势来自"显式的、符号化的场景描述"，而不是 graph 结构本身。
- 下一步：用更依赖场景的评测来放大差异，包括空间/关系问答，以及决策任务（车道、前车）；同时加入 graph-token 变体（graph 编码器 → 投影层）。
